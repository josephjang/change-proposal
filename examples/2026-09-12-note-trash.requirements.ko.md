# Product Requirements: 메모 휴지통과 30일 내 복원

## Summary

실수로 삭제한 메모를 사용자가 직접 복원할 수 있도록 휴지통을 추가한다. 삭제한 메모는 일반 목록과 검색에서 사라지지만, 삭제 시점부터 30일 동안 휴지통에서 되살릴 수 있다. 복원하면 내용과 기존 메모 주소가 유지된다. 만료된 메모를 복원하거나 휴지통 안에서 편집하는 기능은 제공하지 않는다.

## Problem

예시의 현재 상황은 로그인한 사용자가 자기 메모를 작성·검색하는 웹 앱이다. 메모를 삭제하면 즉시 사라지고 되돌릴 수 없어, 잘못 누른 삭제 한 번으로 작성 내용을 잃는다. 확인 대화상자는 실수를 줄여도 이미 일어난 실수를 되돌리지는 못한다.

대상은 같은 계정으로 여러 브라우저 탭에서 메모를 관리하는 개인 사용자다. 공유 문서, 첨부파일, 오프라인 편집은 없는 제품으로 가정한다. 실제 문의 건수나 이탈률 자료는 없으므로 수치 개선을 주장하지 않고, 아래 복원 시나리오의 성공을 완료 기준으로 삼는다. 30일은 이 샘플에서 선택한 제품 정책이지 기존 서비스에서 확인한 정책이 아니다.

## Goals

- 사용자가 다른 사람의 도움 없이 최근에 삭제한 메모를 복원할 수 있다.
- 삭제한 메모가 일상적인 탐색에 섞이지 않고, 복원 가능 여부가 명확하다.
- 휴지통을 추가해도 다른 사용자의 메모나 삭제 전 내용이 잘못 노출되지 않는다.

## Non-Goals

- 공유 메모, 첨부파일, 폴더까지 함께 복원하기. 이 예시의 제품에는 해당 기능이 없다.
- 휴지통에서 편집하기, 즉시 영구 삭제하기, 보관 기간을 사용자별로 설정하기.
- 기능 출시 전에 삭제한 메모나 30일이 지난 메모를 복구하기.
- 기존 백업 정책 변경이나 모든 백업 사본의 즉시 삭제 보장. 여기서의 만료는 앱을 통한 열람·복원 가능 기간이다.

## Requirements

- **R1: 삭제와 화면 반영.** 삭제가 성공한 메모는 다음 조회부터 일반 목록·검색 결과·기존 메모 주소에서 열리지 않는다. 삭제 완료를 확인하지 못했다면 완료로 표시하지 않으며, 통신이 끊겨 결과를 모를 때는 다시 조회해 상태를 확인할 수 있다.
- **R2: 휴지통과 기한 표시.** 사용자는 자기 휴지통에서 복원 가능한 메모의 제목, 삭제 시각, 복원 마감 시각을 볼 수 있다. 마감은 삭제가 처리된 시각에서 정확히 30×24시간 뒤이며, 화면에는 사용자 현지 시각과 시간대를 함께 표시한다. 기한이 지난 항목은 다음 조회부터 목록에 나오지 않는다.
- **R3: 원래 메모로 복원.** 서버에서 복원을 처리하는 시점이 마감 전이면 제목·본문·원래 작성 시각·기존 메모 주소가 유지된 채 복원된다. 일반 목록과 검색에 다시 나타나고 휴지통에서는 사라진다. 복사본을 새로 만드는 방식은 아니다.
- **R4: 만료 후 동작.** 마감 시각과 같거나 이후에는 메모를 열거나 복원할 수 없다. 이미 열어 둔 휴지통에서 만료된 메모의 복원을 시도하면 복원할 수 없다는 안내와 새로고침 수단을 제공한다. 뒤에서 데이터 정리가 늦어져도 복원 기간은 늘어나지 않는다.
- **R5: 접근과 편집 경계.** 다른 사용자의 휴지통이나 메모를 열거나 복원할 수 없다. 삭제 전 열어 둔 편집 화면에서 저장하더라도 휴지통의 내용이 바뀌거나 메모가 되살아나지 않는다. 메모를 다시 편집하려면 먼저 복원해야 한다.
- **R6: 반복 요청.** 이미 휴지통에 있는 메모를 다시 삭제해도 최초 삭제 시각과 마감은 바뀌지 않는다. 이미 복원된 메모에 복원을 다시 요청해도 복사본이 생기지 않는다. 복원 후 사용자가 새로 삭제한 경우에는 그 삭제부터 새 보관 기간을 계산한다.

대표 흐름: 사용자가 메모를 삭제한다 → 검색에서 사라진 것을 확인한다 → 휴지통에서 제목과 복원 마감을 확인한다 → 복원한다 → 원래 주소에서 같은 내용을 다시 연다. 만료 직전의 복원이나 다른 탭의 저장이 겹치는 경우도 같은 요구사항을 만족해야 한다.

## Product Decisions

- **PD1: 확인 대화상자만 추가하지 않고 30일 휴지통을 제공한다.** 대화상자는 삭제 후 뒤늦게 실수를 알아차린 사용자를 돕지 못한다. 무기한 보관은 사용자가 삭제했다고 생각한 내용을 계속 남기므로 선택하지 않는다. 실제 도입 시 복구 수요와 보관 비용을 확인해 기간을 재검토한다.
- **PD2: 휴지통에서는 제목과 기한을 확인하고 복원만 한다.** 본문 미리보기·편집·즉시 영구 삭제까지 제공하는 대안은 복구 기능의 범위를 넓힌다. 첫 버전은 복원 후 기존 편집 흐름으로 돌아가는 데 집중한다. 제목만으로 메모를 구분하기 어렵다는 사용 근거가 생기면 미리보기를 재검토한다.
- **PD3: 복원은 복사가 아니라 원래 메모의 복귀다.** 새 메모로 복사하면 기존 주소가 끊기고 반복 클릭 시 중복을 만들기 쉽다. 따라서 R3의 주소·내용 유지가 기술 선택의 제약이 된다. 구체적인 저장 방식은 [Technical Decisions](2026-09-12-note-trash.design.ko.md#technical-decisions)에서 다룬다.

## Risks

- 삭제한 본문이 30일 동안 보관된다. 실수 복구를 위해 받아들이되 삭제 안내에서 보관 기간을 명시하고, 기한이 지난 뒤에는 앱에서 접근하지 못하게 한다. 백업 정책까지 변경하는 것으로 오해하지 않도록 Non-Goals의 경계를 유지한다.
- 제목만 보여 주므로 비슷한 이름의 메모를 구분하기 어려울 수 있다. 첫 버전에서는 삭제 시각을 함께 제공하는 것으로 수용한다.
- 마감 직전에 클릭해도 서버 처리 시점에는 만료되었을 수 있다. 클릭 시각 기준의 보장 대신 R4의 실패 안내를 제공한다.
- 출시 시 짧은 점검 시간을 허용한다. 이 샘플은 무중단 전환보다 삭제 데이터의 잘못된 노출을 막는 것을 우선한다.
