# Change Proposal: 메모 검색어 한 번에 지우기

[English](2026-09-12-clear-note-search.md) | 한국어

> 학습용 예시 — 가상의 개인 메모 앱을 다루는 Unified Change Proposal입니다. 이 문서 하나가 완전한 Proposal이며, 별도의 Product Requirements나 Technical Design은 없습니다. 실제 사용자 조사나 구현·테스트 결과가 아닙니다. [샘플 읽기 안내](README.ko.md)

## Problem

메모 검색 결과가 없거나 다른 메모를 찾으려는 사용자는 검색어를 직접 모두 지우고 검색을 다시 실행해야 일반 목록으로 돌아갈 수 있다. 검색창 옆에 한 번에 검색을 해제하는 동작이 없어, 검색을 끝내는 간단한 일이 불필요하게 번거롭다.

이 예시에서는 로그인 사용자가 자기 메모를 검색하며, 빈 검색어로 검색하면 일반 목록으로 돌아가는 동작과 검색 오류·재시도 표시가 이미 있다고 가정한다. 검색어는 화면과 주소에 반영되고, 겹치는 검색 요청의 응답은 최신 검색 조건에 맞는 것만 표시하는 기존 처리가 있다. 실제 사용성 조사나 소요 시간 측정은 없으므로 개선 수치를 만들지 않고, 아래 화면 동작으로 완료 여부를 판단한다.

## Goals

- 사용자가 검색어 전체를 직접 선택하지 않고 검색을 해제할 수 있다.
- 마우스와 키보드 사용자 모두 기존 메모 목록으로 돌아갈 수 있다.

## Non-Goals

- 검색 방식·순위·정렬을 바꾸거나 최근 검색어, 자동완성, 새 단축키를 추가하기.
- 새로운 서버 API, 저장 구조, 사용자 설정을 도입하기.
- 메모 휴지통이나 복원 기능을 함께 구현하기. 같은 가상 앱의 별도 변경이다.

## Requirements

- **R1: 지우기 동작 표시.** 검색창에 입력이 있거나 적용된 검색 조건이 있으면 이름이 “검색어 지우기”인 버튼을 표시한다. 둘 다 비어 있을 때는 표시하지 않는다. 검색 결과가 없거나 오류가 나도 이 표시 조건은 같다.
- **R2: 검색 해제.** 버튼을 누르면 검색창과 주소의 검색어를 비우고, 기존의 빈 검색어 검색을 실행해 일반 메모 목록을 요청한다. 입력 중인 검색어와 현재 적용된 검색어가 달라도 둘 다 해제하며, 다른 정렬 조건은 유지한다.
- **R3: 요청 중·실패 상태.** 목록을 불러오는 동안에는 기존 로딩 표시를 사용한다. 실패하면 기존 오류·재시도 동작을 제공하며 검색어는 빈 상태로 유지한다. 앞선 검색 응답이 늦게 도착해도 해제하기 전의 검색 결과로 화면이 되돌아가지 않는다.
- **R4: 키보드와 포커스.** 버튼은 키보드로 이동해 Enter 또는 Space로 실행할 수 있고, 보조 기술에 “검색어 지우기”라는 이름이 전달된다. 실행 후에는 빈 검색창에 포커스가 있어 바로 새 검색어를 입력할 수 있다.

## Decisions

- **D1: 검색 결과 화면의 별도 복귀 링크보다 검색창 옆 버튼을 제공한다.** 검색어가 보이는 위치에서 해제할 수 있고, 결과가 있든 없든 같은 동작을 찾을 수 있다. 새 단축키만 제공하는 대안은 발견하기 어려워 선택하지 않는다. 검색창이 숨겨지는 화면이 추가되면 배치를 재검토한다.
- **D2: 기존 빈 검색어 검색 경로를 재사용한다.** 이전에 불러온 전체 목록을 별도로 캐시하는 대안은 오래된 메모를 보여 주거나 두 목록의 상태를 따로 관리하게 만든다. R2/R3은 기존 검색·오류·응답 순서 처리에 연결하며, 새 서버 기능이나 영구 상태를 만들지 않는다. 그래서 이 변경에는 별도의 기술 설계 문서가 필요하지 않다.

## Risks

- 버튼을 잘못 누르면 입력하던 검색어를 잃을 수 있다. 메모 자체는 바뀌지 않고 검색어를 다시 입력할 수 있으므로, 확인 대화상자나 실행 취소를 추가하지 않는 것으로 수용한다.
- 검색 해제도 기존 검색과 같은 통신 실패를 겪을 수 있다. 즉시 목록이 나타난다고 약속하지 않고 R3의 로딩·재시도 동작으로 처리한다.
