# change-proposal

제품이나 시스템의 변경 뒤에 있는 **판단**을 기록하는 최소 실천법과, 나중에 — 필요할 때 하나씩 — 더할 수 있는 패턴 카탈로그.

**변경 제안(Change Proposal, CP)**은 왜 이 변경을 하는지, 무엇을 일부러 하지 않는지, 무엇을 결정하고 무엇을 버렸는지, 무엇을 확인했는지, 무엇을 감수하거나 미뤘는지를 적은 한 장짜리 마크다운 파일이다. 사람이 쓰고, 저장소 안에 살며, 변경과 같은 PR로 머지된다.

이것이 코어의 전부다. 그 외의 모든 것 — 크기 판정, 리뷰 단계, AI 초안 규칙, 불변성, 메타데이터, 에이전트 연동, 도구, 번역 — 은 **패턴**이다: 문서화되어 있고, 선택이며, 독립적으로 도입할 수 있고, 코어가 전제하지 않는다.

영어판(`README.md`)이 정본이다. 이 문서는 번역이며, 어긋나면 영어판을 따른다.

## 문서

| 경로 | 내용 |
|---|---|
| `docs/concept.md` (`docs/ko/concept.md`) | 변경 제안이 무엇이고 무엇이 아닌지, 코어가 일부러 정하지 않는 것 |
| `docs/principles.md` (`docs/ko/principles.md`) | 원칙 10개와 그 이유 |
| `docs/rules.md` (`docs/ko/rules.md`) | 코어 규칙 — 여덟 개. 패턴 규칙은 각 패턴 카드에 있다 |
| `docs/patterns/README.md` (`docs/ko/patterns.md`) | 패턴 카탈로그: 각 패턴이 더하는 것, 신호, 조합 방법, 조합 예시 |
| `docs/patterns/<name>.md` | 패턴별 카드, 자기완결형: 의도, 신호, 더하는 것, 규칙, 비용, 제거 (영어) |
| `templates/change-proposal.md` (`templates/ko/`) | 코어 템플릿 |
| `docs/changes/` | 이 저장소 자신의 제안들 |

이 저장소에는 문서만 있다. 스크립트, 스킬, 설정 파일, 코어 외의 템플릿은 싣지 않는다. 도구가 관련된 패턴(`lint-gate`, `agent-skills`, `agent-context`)은 도구가 무엇을 해야 하는지를 기술하고, 구현은 도입하는 쪽에 맡긴다.

## 코어 다섯 줄

1. 관찰 가능한 동작을 바꾸는 변경은 `docs/changes/YYYY-MM-DD-<slug>.md`에 제안을 두고, 코드와 같은 PR로 머지한다. 동작이 안 바뀌면 PR 설명에 그렇다고 적는다.
2. 제안은 다섯 섹션이다: **문제(Problem)**, **비목표(Non-goals)**, **결정(Decisions)**, **검증(Verification)**, **감수한 리스크와 미룬 것(Risks & deferred)**.
3. 코드가 말할 수 없는 것을 기록한다: 왜, 무엇을 뺐나, 무엇을 왜 버렸나, 실제로 무엇을 확인했나, 무엇을 알고 감수했나.
4. 사람이 쓴다. 한 장에 들어간다. 빈 섹션은 지운다.
5. 그 외에는 아무것도 요구하지 않는다. 신호가 보일 때 패턴을 더한다.

## 프로세스가 아니라 패턴

코어는 라이프사이클, 메타데이터, 크기 판정, 리뷰 단계, AI의 참여 방식, 머지된 제안의 처리, 작성 언어, 도구 중 어느 것도 정하지 않는다. 각각은 도입 신호가 명시된 패턴이다. `docs/patterns/README.md` 참고.

## 언어

영어가 정본이고, 한국어 번역이 뒤따르며 어긋나면 영어를 따른다. 제안 자체를 다른 언어로 써도 되는지는 `multilingual-records` 패턴이 정한다.

## 기여

이 저장소의 변경은 이 실천법 자체를 쓴다: 개념, 규칙, 패턴, 템플릿을 바꾸는 변경은 `docs/changes/`에 제안을 남긴다. `CONTRIBUTING.md` 참고.
